# TODO: согласовать срок действия команд с прошивкой

Backend является источником истины для времени создания и срока действия команды.

## Выбранный контракт

- `expiresAt` сохраняется в формате ISO 8601 и используется в БД, журналах и интерфейсе.
- Для микроконтроллера backend дополнительно возвращает `expiresInMs`, рассчитанное на момент формирования ответа `GET /commands`.
- Прошивка сравнивает `expiresInMs` с локальным `millis()` и не реализует календарный парсер ISO 8601.

Пример:

```json
{
  "commandId": 123,
  "type": "SET_SETPOINT",
  "createdAt": "2026-07-18T10:00:00.000Z",
  "expiresAt": "2026-07-18T10:05:00.000Z",
  "expiresInMs": 184000,
  "payload": {
    "setpointValue": 23.5
  }
}
```

## Задачи backend

- [ ] В `getDeviceCommands()` вычислять `expiresInMs = max(0, expiresAt - responseCreatedAt)`.
- [ ] Не возвращать команды, уже просроченные на момент выборки.
- [ ] Сохранять `expiresAt` в ответе в ISO 8601.
- [ ] Добавить `expiresInMs` в Zod-схему и TypeScript-контракт ответа контроллеру.
- [ ] Для команд без `expiresAt` назначать срок при создании; до миграции не выдавать чувствительные команды без срока.
- [ ] Добавить тесты для актуальной, пограничной, просроченной и бессрочной команды.
- [ ] Проверить перевод просроченной команды в `expired` до выдачи устройству.
- [ ] Обновить документацию REST API и примеры JSON.
- [ ] Выполнить изменение совместно с прошивкой.

## Критерии приёмки

- Просроченная команда не выдаётся либо отвергается устройством как `expired`.
- Устройство не зависит от RTC и не разбирает ISO 8601.
- `expiresAt` остаётся единым абсолютным значением для БД, журналирования и интерфейса.
- Повторная доставка не продлевает исходный срок команды.

## Принятые правила протокола

- Микроконтроллер инициирует все соединения с backend.
- Формат сообщений — JSON в кодировке UTF-8.
- Все сообщения устройства содержат `protocolVersion`, `messageId`, `deviceUid`, `bootId`, `deviceSequence` и `deviceUptimeMs`.
- Телеметрия и журналы допускают повторную передачу; дубликаты определяются с учётом `bootId` и последовательного номера.
- Команда считается фактически применённой только после согласования ACK и последующего сообщения `state` либо телеметрии.
- Машинное обучение не является локальным алгоритмом регулирования и не формирует команды, отличные от стандартной `SET_SETPOINT`.
- Прошивка не разбирает календарное время ISO 8601 и использует только относительный срок `expiresInMs`.
- Повторная выдача команды не продлевает её исходный срок действия.
